# 蓝绿可空字段扩展门禁

2026-09-21 用户批准在旧版读写兼容的前提下支持这类数据库字段迁移。关联 `CUST-OPS-007`，沿用 `CUST-OPS-001` 的标签发布流程；这不是关闭迁移门禁。

## 允许范围

- 仅新增 SQL 文件，文件中只有一条 `ALTER TABLE <表> ADD COLUMN IF NOT EXISTS <列> <类型>;`，可带独占一行的注释。
- 字段允许 NULL，无默认值、约束、回填、生成表达式或索引；类型限 PostgreSQL 内置 `jsonb/text/boolean/smallint/integer/bigint/uuid`。
- 必须在 `deploy/blue-green/expand-approvals.json` 留下针对活动旧提交的兼容审查，绑定 SQL 摘要、目标字段及旧版读写实现摘要。未来同类迁移仍需核验受影响旧版代码，不能仅凭 SQL 形状推断兼容。
- 历史 SQL 修改、删除、重命名、Ent schema 变化和其他未知文件继续拒绝；迁移目录内测试文件新增或修改不视为生产 DDL。
- 当前审批覆盖 `v0.1.242` 的 `ee1c56f75a38c8678ed338a4a1fecad51b08593c` 到 `238b_content_moderation_engine_meta.sql`：审核日志旧版明确指定列名，新字段不参与旧版读写，无余额或账单更新。

## 执行保护

1. 发布证据仍绑定固定 SHA、镜像摘要、完整 CI 和安全扫描；迁移策略随候选环境注入，不修改生产 `.env`、Compose 或业务参数。
2. 候选启动先核对真实 `schema_migrations` 和嵌入 SQL。任何额外待执行迁移、历史摘要不匹配或审批内容变化，都在 DDL 前失败。
3. 获批扩展仍使用既有迁移 advisory lock。每个文件独立事务，包含 DDL 和迁移记录；对目标表使用 `ACCESS EXCLUSIVE ... NOWAIT`，锁被占用立即失败，不排队等待旧请求。
4. 事务级 `lock_timeout=1s`、`statement_timeout=5s`，事务上下文最多 10 秒；设置不泄漏到业务连接池。不停止业务会话，不在数据库全局改超时。
5. 只接受既有普通表，拒绝分区、继承和类型表；完成后核对字段的实际类型、可空性、默认值和生成属性。`IF NOT EXISTS` 不能掩盖不兼容的同名字段。
6. 扩展候选启动期间 `restart=no`。迁移失败保留旧实例与当前流量，不自动重启候选；失败候选及 `preparing` 状态保留供核查。依赖与合成流通过后才恢复 `on-failure`，随后执行既有切流和排空流程。

## 风险与恢复

- 新旧实例共享数据库，迁移在切流前提交。新增可空列无需重写表，但获锁后仍会短暂持有排他锁；不能保证业务绝对零延迟。
- 失败事务回滚；已经成功提交的扩展保留。应用回退不执行反向删列，不恢复旧数据库覆盖新写入。
- 兼容审批不代替备份。生产发布前仍须核对实际待执行清单、备份情况、长事务、数据挂载、原有资源参数和入口健康。
- 单元测试覆盖不安全 SQL、错误基线/摘要、未知迁移和候选失败不切流；隔离 PostgreSQL 测试覆盖旧版写入、新字段写入、锁冲突立即失败、配置不泄漏、重复启动和字段漂移。生产负载下的零影响不在这些测试的证明范围内。
- 既有一小时观察及到期强制退役策略不变；它可能中断旧长请求，不能和迁移的结构兼容性混为一谈。
