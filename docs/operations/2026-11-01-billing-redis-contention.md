# 2026-11-01 余额预留与 Redis 并发阻塞修复

关联功能：`CUST-BILL-008`、`CUST-OPS-001`、`CUST-OPS-004`。

## 故障证据

- 用户 1054 在北京时间 2026-11-01 16:21:34.209 被拒绝时，余额 13619.786259、预留合计 13619.422462、本次估算 0.602008。现有规则按可用余额拒绝，但错误统一归为余额不足 403。不能据此认定全部预留都是真实消费或全部都是残留。
- 请求 `d0200749-5a5d-49ed-8551-723d8d6dfe16` 在 16:18:42 获取用户并发槽位时发生 Redis I/O 超时，尚未选上游账号；渠道 3 的这类 503 没有转发到上游。
- Redis 最近慢日志集中在用户 1054 的预留脚本；旧脚本 SHA 为 `ba6e71de4ac29d20402dc52f6b30b1ff126ca0bf`，每次 `HVALS` 全量求和。6500 条规模时，线上观察到每次约 10 至 15 毫秒。
- 本地复现并转为回归：写成功但响应丢失时句柄丢弃；释放失败被 `sync.Once` 永久吞掉；同 ID 重试把自己的旧金额计入他人预留并拒绝。

## 修复契约

保留 `billing:inflight:{uid}` 与 `billing:inflight_amt:{uid}`，以及对应 scope 明细键。新增每维度 `:total`、`:prior` 和每预留 `:done:{id}` 完成标记。完成标记至少保留 30 分钟，若当前明细 TTL 更长则跟随延长。完成标记仅表示清理或终结，不扣余额。

共享 HASH `billing:inflight:accounting` 保存 `mode`、`generation`、`owner`；脚本每次原子读取。标记缺失、未知模式或混跑时按兼容统计；累计代次不匹配或元数据缺失时重建。正常累计只做有界清理和增减，单次最多处理 128 条过期记录，剩余批次继续受原操作 context 限制。

预留服务在网络写入前登记清理目标。结果未知仍交接句柄给 handler 和计费任务；引用归零后先尝试释放，只有所有维度收到 Redis 确认才记为完成。余额预留与槽位分别使用去重补偿队列，避免一种故障挤占另一种清理：每队列 4 个 worker、最多 16384 个含执行中任务、每次 2 秒、100 毫秒至 5 秒退避；进程退出额外排空预算 2 秒，剩余项依赖原 TTL。

管理员日志 `billing.inflight_result_unknown`、`billing.inflight_limit`、`billing.inflight_release_pending` 和 `gateway.slot_operation_failed` 记录关联 ID、金额、阶段或耗时。私有生命周期 socket 的 `/state` 返回 `redis_cleanup` 累计指标：入队、确认、重试、队列满、TTL 兜底。告警事件为 `redis.cleanup_retry` 和 `redis.cleanup_ttl_fallback`，重复高频告警按累计计数节流。

余额为正但预留不足：HTTP 429，`rate_limit_error`，`balance_inflight_limit`，`Retry-After: 1`；Google 协议保持 `RESOURCE_EXHAUSTED` 并附带同名 reason。真实余额不足继续 403。Redis 槽位故障保持可重试 503，细分为 `gateway_concurrency_backend_unavailable`，不绕过并发限制。

## 蓝绿与回滚

1. 使用本次或后续支持统计模式门禁的 `deploy.py` 执行发布、恢复和回滚，不调用旧标签自带的历史发布脚本重新创建旧实例。
2. 候选启动和激活前，原子写入并确认 `compat`；读写或确认失败即停止，不启动或切流。
3. 新旧混跑期间维持兼容统计，不提前启用累计。
4. 正常或强制退役都必须先核验旧容器身份并移除；活动实例通过私有 socket 声明 `billing_inflight_aggregate_v1`，且只有活动槽与容器存在后才启用 `aggregate`、新代次。重复确认同一 owner 保持当前代次。
5. 回滚先确认 `compat`，再恢复旧实例；旧版不支持累计时保持兼容。无法确认任一步则保留现状并停止操作。不得直接把模式改为累计来绕过门禁。

无需数据库迁移。禁止清空生产预留、修改客户余额、扩连接池或调整生产资源预算。本轮保持 `gateway.response_header_timeout: 3600`、按用户串行扣费和 `GATEWAY_USAGE_RECORD_TASK_TIMEOUT_SECONDS=5`。
