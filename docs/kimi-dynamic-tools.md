# Kimi 动态工具契约与渠道兼容

功能编号：`CUST-GW-016`。管理入口为“二开功能 → 网关配置 → Kimi 动态工具契约与渠道兼容”，字段为 `kimi_dynamic_tools_enabled`，默认关闭。

## 生效范围

- 仅 API Key 所属分组类型为 `kimi` 的 Chat Completions 入站生效，不按分组名称或模型名称匹配，不影响综合分组和其他平台分组。
- 契约校验发生在并发排队和流式响应头提交之前；入口保留原始请求供审计、计费预估和会话识别使用。转发层在协议转换前将合法声明合并至顶层工具，再交给既有 Chat Completions、Responses 或 Anthropic 转发链。
- 不为 Messages、Responses 入站新增动态工具协议；Responses 形状请求没有 `messages` 时保持原样。
- 开关按请求冻结，重试和切换账号不重复合并，也不会因管理员中途修改开关而改变校验结果。旧配置缺失字段按关闭处理，旧客户端部分更新不会清空此开关。

## 契约校验

- `messages[].tools` 只允许位于原始 `role=system` 消息。user、assistant、developer、tool 消息中的工具声明返回 HTTP 400，不先将 developer 改为 system。
- 同一声明消息允许 `content` 缺失、空字符串或 null，拒绝非空字符串、空白正文及其他正文类型。普通 `role=tool` 的执行结果允许携带正文，但必须提供非空字符串 `tool_call_id`。
- 工具列表必须是数组，每项必须是 `type=function` 对象，并携带函数对象和合法名称。名称以 ASCII 字母或下划线开头，其余仅允许字母、数字、下划线、连字符，最长 256 个字符。
- 检查同一声明、跨声明、动态与顶层工具之间的重名。存在动态声明时，共存的顶层工具也检查结构及重名，不默默覆盖或去重。
- 可选的 parameters 必须是对象，description 必须是字符串，strict 必须是布尔值。嵌套 JSON Schema、strict=false 及扩展字段保留，不代替上游执行完整 JSON Schema 校验。
- 拒绝请求对象、消息对象、工具对象和函数对象中的重复或大小写歧义键，避免不同解析器选择不同角色或工具。错误只包含字段路径和规则，不回显用户正文或完整工具定义。

## 渠道兼容

校验通过后，将动态工具按消息顺序合并到顶层 `tools`，已有顶层工具排列在前。删除纯工具声明消息；含额外元数据的消息保留在原位置，并移除其工具声明。普通消息、历史 tool_calls、tool_call_id、reasoning_content 和未知扩展数据不变。转换后至少保留一条对话消息。

`tool_choice`、输出额度和思考设置不因本功能改变。工具调用仍由真实上游模型生成，成功响应及 usage 沿用现有转发链，不伪造 HTTP 成功、工具调用或 Token 数。

这是面向只支持顶层工具渠道的兼容模式，不等同于原生动态工具实现。将中途声明移到顶层会改变工具的历史位置和提示前缀，可能影响缓存命中、输入 Token 和生成行为；缓存敏感或完整支持原生协议的渠道应保持关闭。没有动态声明的普通请求不会重写正文和 Token；`assistant_hello` 基准差异不在本功能修复范围内。

现有五项“Kimi 参数兼容重试”开关与本功能独立。严格 KVV 验证建议继续关闭这些参数重试开关，避免非法参数被另一个功能修正后重试成功。

## 验证基准与边界

动态工具契约以 MoonshotAI/Kimi-Vendor-Verifier 固定提交 `66092cf444c97356c0e11c5078c67116390615d9` 的 `tests/k3_features/test_dynamic_tools.py` 为回归依据。官方动态工具文档要求声明消息不携带 content；该版 KVV 合法用例携带 `content: ""`，负向断言针对非空正文。本兼容模式接纳空正文，随后移除纯声明消息。

本地测试覆盖声明位置、多个工具与全局共存、Schema/历史保留、错误角色及正文、非法定义与重名、开关持久化/隔离/默认值、排队前400、流式和非流式工具响应透传、参数重试及协议桥接。模拟上游测试不代表真实渠道的 KVV 通过率，也不能证明完整 KVV 认证。

发布后应先在测试 Kimi 分组启用，针对真实渠道复跑动态工具用例，检查工具名称、参数、finish_reason、SSE 终态和单次入账。关闭本开关后，新请求恢复既有透传；无需数据库迁移。本次不自动修改生产配置或部署。
